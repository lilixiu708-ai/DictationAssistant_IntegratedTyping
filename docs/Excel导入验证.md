# Excel 导入验证

**范围：Word / Excel 导入插件 1.1.0，已独立公开。** 用户 `.xlsx` 样本已在 Linux 完成全量独立比对，Windows 已通过合成样本 CLI、R6 装载及程序窗口检查；其他 Excel 格式、公式缓存与 Windows 真实 Excel GUI 导入未验证。R6 本体、同步打字 1.3.1 和历史 Word 导入 1.0.1 的资产均不因此变更。

## 读取库与规则

选用 [ExcelDataReader 3.9.0 固定源码](https://github.com/ExcelDataReader/ExcelDataReader/tree/f3343f5524518923bdeb4801e5003c0417fd35f3)，使用底层只读接口；其 net8.0 资产无传递依赖，能覆盖本次需要的旧 `.xls` 与 `.xlsb`。已参考 [ClosedXML 固定源码](https://github.com/ClosedXML/ClosedXML/tree/09f2f21a60e821ce7fb18ca3576b272e5dd6d921) 和 [Open XML SDK 固定源码](https://github.com/dotnet/Open-XML-SDK/tree/431ab05cf160248cc3885a4a766026d4f8243792)：前者偏向现代 Excel 文档的读写编辑，后者面向 Open XML 容器；本次以多格式读取为主，不引入编辑或公式计算能力。

实现范围为 `.xlsx`、`.xls`、`.xlsb`、`.xlsm`。每张工作表独立分区，保留原工作表顺序与列位置，再交由宿主预览选列。字符串不裁剪、不规范化，保留原始 Unicode 与空白；合并单元格只保留左上角锚点，不向其他格复制。公式只读取已有缓存，不重新计算，也不运行宏。

## 本轮实际结果与待执行范围

本轮在 Linux 读取用户提供的 `.xlsx`，将原始插件 JSON 与独立基线逐项比较：19 张工作表、2,886 个位置、2,683 份非空文本逐字符零差异。全部 92 个合并区域均仅保留锚点，2 处空行及 `SourceLabel` 的真实行号正确，Unicode、换行、尾部空格和重复项保留。

通过现有宿主 CLI 对每张工作表的每列执行 56 次导出，覆盖 2,683 个非空单元格；按宿主原有的空白折叠规则比较，结果全部一致。这与插件读取阶段的原始文本逐字符比对分别记录，不把导出时的空白处理写成原始单元格内容变化。
