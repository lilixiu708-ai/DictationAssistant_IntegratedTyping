## 测试配置

- 词表两行：`Monday`、`accommodate`。
- 自动播报间隔设为 `2`，次数/词设为 `2`。
- 插件打字时限设为 `3` 秒。
- 语音选英文，音量保持可听。

## 关键场景

1. 点击「同步打字」。后台读取核对完成后，显示「已读取 2 / 2 条」，不再显示「准备就绪 · 0 / 2」；读取完成前不能开始练习。开始前能设置 `3` 秒并保存，介绍文字放大并居中，倒计时与本轮进度条隐藏。插件管理能看到同步打字插件「已加载」，并保留 Word 导入插件。
2. 开始后始终显示「播放中」。第一遍完整结束后等待 2 秒，再开始第二遍。两遍中及间隔中都看不到输入框，也看不到正确单词。
3. 第二遍最后一段声音结束后才显示打字输入框，并开始从 3 秒倒数。读秒上方没有白色下划线占位条，练习时的完成进度条仍保留。可以打字；输入 `Monday` 并按 Enter，界面不显示对错，自动切换第二词。
4. 第二词不输入，3 秒后自动记录空字符串。直到第二词结束才显示整轮成绩：`1 / 2`，正确率 `50.0%`，并列出逐词对照。
5. 启用/关闭「忽略大小写」进行下一轮：`MONDAY` 默认视为正确，关闭时应视为错误；首尾空格不影响判分。
6. 点击「导出成绩 CSV」，用 Excel/记事本检查第一词、第二词（空白超时）及 UTF-8 中文表头。
7. 在第 2 次读音过程中点击「取消并关闭」，声音停止、不显示部分成绩、主窗口恢复。
8. 按住 Enter 跨越上一题与下一题的状态转换，不能使下个词未经输入就自动提交。
9. 打开原 Word 插件，导入《第二周听力词汇.docx》的第一张表并在预览中确认 40 词；开启同步打字后显示「已读取 40 / 40 条」，最终应处理 40 词；词表顺序和导出一致。该数量核对以当前编辑器词表为基准，不代表已检测原 DOCX 的所有内容。
10. 将 `Plugins/SynchronousTyping` 文件夹移走并重启：菜单入口给出明确的插件缺失提示，原有 Word 导入功能仍可用。

## 边界条件

- 时限输入 `0`、`301`、非整数或空白 → 拒绝启动并显示提示。
- 词表空白 → 宿主阻止启动；只有 1 条时仍正常完成并计分；重复词条保留。
- 在两条词之间加入空白行，再追加一条相同词条 → 读取数量为 `3 / 3`，空白行不计数，重复词条保留。
- 读取失败、无效词条或数量不符 → 禁用开始按钮并提示错误；检查 `%APPDATA%\DictationAssistant\Plugins\SynchronousTyping\CrashLogs` 中自动保存的日志。核对失败阶段、实际/理论数量、可定位时从 1 开始的失败序号、版本及异常详情；连续产生日志时最多保留最近 20 份。日志不主动附加整份词表或作答内容，但第三方异常可能带词条或文件路径，分享前检查。
- 语音合成错误 / 没有音频设备 → 显示失败，不给部分成绩。
- SDL 音频回调消耗最后 PCM 缓冲后再释放输入（硬件 / 驱动可能存在极小播放延迟，需实机试听）。

## R5 / 插件 1.1.0 的翻译提示与本地设置

以下场景在下载后的本机程序操作，使用自己的词表和服务配置；记录结果时不要附带个人配置文件。

1. 在准备页打开「录入／提前翻译」，录入两列原词与译文，保存后重新打开；译文应恢复，主词表和播报内容不变。
2. 开始练习，分别显示与隐藏翻译；提示只在播报结束后的打字阶段出现，切换后仍能继续输入，判分核对原词。
3. 下载后在程序内打开「翻译 API 设置」，检查输入遮挡、保存、重开后不回显、替换与删除；Windows 本地保存文件不应含明文。
4. 使用「仅本次使用」后关闭编辑窗口，再次打开时不应保留该临时配置；未配置服务时，手动录入和离线练习仍可用。
5. 在本机完成提前翻译并校对保存，再断开网络练习；已有译文应可正常显示，练习期间不应等待翻译请求。
6. 另行核对不同 Windows 账户或设备无法直接读取复制来的绑定文件，以及请求失败、额度不足、取消操作等行为；只记录结果，不记录密钥或原始设备标识。

## 输入、长列表与资源占用

以下是实机复现步骤，不是性能测量结果。比较不同版本时使用同一台电脑、相同词表、语音、播报设置和窗口大小；升级版解压到独立空目录，避免残留库影响结果。

1. 在任务管理器中记录启动稳定后的内存与 CPU 占用，注明 Windows 版本、CPU、内存、语音来源和程序版本。
2. 使用至少 100 条词表开始练习，在输入框持续打字、删除、移动光标，切换英文和中文输入法。观察文字是否跟手，倒计时变化时是否卡顿或导致输入框移动；记录峰值 CPU、峰值内存及卡顿发生时的步骤。
3. 保持相同设置继续切换词条，检查后台语音初始化期间窗口能否响应。播报仍应先完整结束，再允许输入；计时刷新减少后，超时提交仍须准确。
4. 完成较长词表后滚动成绩列表，检查进度、正确率、首尾记录及重复词条；顶部摘要和底部按钮应保持可用。重复滚动，记录内存是否随滚动持续增长、是否出现空白行或内容错位。
5. 导出 CSV，核对总行数、顺序、空白答案及首尾记录与成绩一致。关闭成绩窗口后再练习数轮，观察是否出现持续的资源增长；不要把一次 GC 前后的差异直接当作泄漏或优化幅度。

需要快速构造较长的待核对成绩时，可以使用短时限和重复词条；不要因此省略正常播报与输入时序检查。比较结果应附词条数、运行时长和采样方式。
