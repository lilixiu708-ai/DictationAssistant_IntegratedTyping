# DictationAssistant 插件开发指南

本文对应 Windows 文档导入插件接口第 1 版，更新于 2026 年 10 月 19 日。你可以编写独立的 .NET DLL，将 Word、特定格式的文本或其他文档解析成表格和词条，交给软件预览、选择列并导入。插件编译后放入应用的 `Plugins` 子目录，重启即可加载，无需重新编译主程序。

当前接口的职责是**读取文档并返回文本数据**。预览窗口、替换或追加词表、撤销、随机顺序和语音播放由主程序负责。接口没有添加菜单、操作编辑器、控制音频或执行脚本的扩展方法；后续若需要这些功能，应先设计相应的宿主接口。

## 一 安装包与源码中的位置

开发需要 .NET 10 SDK；插件项目目标框架为 `net10.0`。Windows 完整应用包已经自带运行时，普通用户安装插件不需要安装 SDK。

| 位置 | 用途 |
|---|---|
| 应用目录中的 `Plugins/<插件文件夹>/` | 用户安装插件的位置 |
| 源码中的 `src/DictationAssistant.Plugin.Abstractions/` | 共享接口和返回数据类型 |
| 源码中的 `src/DictationAssistant.App/Plugins/` | 清单检查、程序集加载与插件状态 |
| 源码中的 `src/DictationAssistant.App/Importing/` | 后台读取、结果验证与预览转换规则 |
| 源码中的 `plugins/DictationAssistant.Importers.Docx/` | 正式的 Word 词表导入插件 |
| 源码中的 `sdk/examples/PhrasesImporter/` | 可直接编译的逐行短语示例 |
| SDK 包中的 `lib/` | 契约 DLL 和 XML 文档 |
| SDK 包中的 `examples/PhrasesImporter/` | 同一份逐行短语示例 |

应用只扫描 `Plugins` 的**直接子文件夹**。例如，Word 插件安装后应包含以下文件：

| 相对于应用目录的路径 | 说明 |
|---|---|
| `Plugins/docx-vocabulary/plugin.json` | 插件清单 |
| `Plugins/docx-vocabulary/DictationAssistant.Importers.Docx.dll` | 入口程序集 |
| `Plugins/docx-vocabulary/DictationAssistant.Importers.Docx.deps.json` | 发布生成的依赖描述 |
| `Plugins/docx-vocabulary/其他依赖文件` | 插件需要的私有 DLL 或资源，按发布输出保留 |

不要将 ZIP 本身放入 `Plugins`，也不要额外套一层包目录，使 `plugin.json` 变成孙级路径。

## 二 从可编译示例开始

SDK 中的 `PhrasesImporter` 读取 `.phrases` 文本文件，每个非空行作为一个完整短语。这里使用专用扩展名，避免与主程序已有的 `.txt` 打开功能混淆。示例文件内容可以是：

```text
take part in
be responsible for
according to
```

项目由下面三个文件组成。代码也是 SDK 中实际提供的示例，可以在 SDK 或完整源码中直接编译。

### PhrasesImporter.csproj

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <AssemblyName>Example.PhrasesImporter</AssemblyName>
    <Version>1.0.0</Version>
  </PropertyGroup>
  <ItemGroup Condition="Exists('../../lib/DictationAssistant.Plugin.Abstractions.dll')">
    <Reference Include="DictationAssistant.Plugin.Abstractions">
      <HintPath>../../lib/DictationAssistant.Plugin.Abstractions.dll</HintPath>
      <Private>false</Private>
    </Reference>
  </ItemGroup>
  <ItemGroup Condition="!Exists('../../lib/DictationAssistant.Plugin.Abstractions.dll')">
    <ProjectReference Include="../../../src/DictationAssistant.Plugin.Abstractions/DictationAssistant.Plugin.Abstractions.csproj">
      <Private>false</Private>
      <ExcludeAssets>runtime</ExcludeAssets>
    </ProjectReference>
  </ItemGroup>
  <ItemGroup>
    <None Update="plugin.json" CopyToOutputDirectory="PreserveNewest" CopyToPublishDirectory="PreserveNewest" />
  </ItemGroup>
</Project>
```

在 SDK 目录结构中，项目通过 `../../lib/` 引用契约 DLL；在完整源码中，若这个 DLL 不存在，则通过 `../../../src/` 引用契约项目。相对路径以项目文件所在目录为准，移动项目时需要调整。

`EnableDynamicLoading` 用于将项目配置为动态加载插件。`Private=false` 避免将另一份契约 DLL 复制到插件输出；源码项目引用中的 `ExcludeAssets=runtime` 同样避免把契约作为插件的私有运行依赖。宿主和插件必须使用宿主已经加载的同一份契约类型。Microsoft 的[插件项目教程](https://learn.microsoft.com/en-us/dotnet/core/tutorials/creating-app-with-plugin-support)说明了这一引用方式。

### plugin.json

```json
{
  "id": "example-phrases",
  "name": "逐行短语导入示例",
  "version": "1.0.0",
  "description": "读取 .phrases 文本文件，每个非空行作为一个完整短语。",
  "apiVersion": 1,
  "extensions": [".phrases"],
  "entryAssembly": "Example.PhrasesImporter.dll",
  "entryType": "Example.PhrasesImporter.PhrasesImporter"
}
```

### PhrasesImporter.cs

```csharp
// Minimal document-import plugin example, 2026-10-19. AGPL-3.0-or-later.
using System.Text;
using DictationAssistant.Plugin.Abstractions;

namespace Example.PhrasesImporter;

public sealed class PhrasesImporter : IDocumentImporter
{
    public PhrasesImporter() { }

    public async Task<ImportDocument> ReadAsync(
        Stream content, string fileName, CancellationToken cancellationToken)
    {
        ArgumentNullException.ThrowIfNull(content);
        ArgumentNullException.ThrowIfNull(fileName);
        cancellationToken.ThrowIfCancellationRequested();
        if (!content.CanRead)
            throw new InvalidDataException("文件流不可读。");
        if (!string.Equals(Path.GetExtension(fileName), ".phrases", StringComparison.OrdinalIgnoreCase))
            throw new InvalidDataException("本示例只读取 .phrases 文本文件。");
        if (content.CanSeek && content.Length > 64L * 1024 * 1024)
            throw new InvalidDataException("文件超过 64 MiB。");

        using var reader = new StreamReader(content, new UTF8Encoding(false, true),
            detectEncodingFromByteOrderMarks: true, bufferSize: 4096, leaveOpen: true);
        var rows = new List<ImportRow>();
        var lineNumber = 0;
        long readCharacters = 0;
        while (await reader.ReadLineAsync(cancellationToken).ConfigureAwait(false) is { } line)
        {
            cancellationToken.ThrowIfCancellationRequested();
            lineNumber++;
            readCharacters += line.Length + 1L;
            if (lineNumber > 50_000 || line.Length > 200_000 || readCharacters > 2_000_000)
                throw new InvalidDataException("本示例最多读取 50000 行及约 200 万字符，单行最多 20 万字符。");
            if (line.Contains('\0'))
                throw new InvalidDataException("文件包含二进制内容，请提供文本短语。");
            if (string.IsNullOrWhiteSpace(line))
                continue;
            if (rows.Count >= 10_000)
                throw new InvalidDataException("本示例最多导入 10000 条短语。");
            rows.Add(new ImportRow
            {
                SourceLabel = $"第 {lineNumber} 行",
                Cells = [line],
                IsHeader = false
            });
        }
        if (rows.Count == 0)
            throw new InvalidDataException("文件中没有非空短语。");

        return new ImportDocument
        {
            SuggestedSectionIndex = 0,
            Sections =
            [
                new ImportSection
                {
                    Name = "短语列表",
                    Kind = ImportSectionKind.Paragraphs,
                    Columns = ["短语"],
                    SuggestedColumnIndex = 0,
                    Rows = rows.ToArray()
                }
            ],
            Warnings = []
        };
    }
}
```

示例保留每一行原始文字，未自行去重或打乱。`SourceLabel` 中的行号便于定位来源；真正传给预览的短语位于 `Cells[0]`。`leaveOpen:true` 保证释放 `StreamReader` 时不会提前关闭宿主的文件流。

示例默认按 UTF-8 读取，并识别 Unicode BOM。它对行数、字符数和单行长度设置了适合演示的小上限；处理压缩文件或复杂格式时，应采用正式 DOCX 插件中的实际读取字节计数、解压大小和结构深度限制。

## 三 清单字段与加载要求

每个插件文件夹需要一个 `plugin.json`，文件大小不能超过 64 KiB，JSON 深度不能超过 16。属性名按不区分大小写读取，建议使用示例中的小驼峰写法。

| 字段 | 必需 | 当前规则 |
|---|---|---|
| `id` | 是 | 1–100 个 ASCII 字母、数字、点、下划线或短横线；首字符须为字母或数字 |
| `name` | 是 | 显示名称，非空，最多 200 字符，不含控制字符 |
| `version` | 是 | 显示版本，非空，最多 80 字符；建议采用 `1.0.0` 形式 |
| `apiVersion` | 是 | 当前必须为整数 `1` |
| `extensions` | 是 | 1–32 个扩展名，带开头的点；点后为 1–16 个 ASCII 字母或数字 |
| `entryAssembly` | 是 | 插件目录中的 DLL 文件名，不能包含目录、绝对路径或 `..` 路径跳转 |
| `entryType` | 是 | 入口类型的完整名称，包含命名空间，大小写与代码一致 |
| `description` | 否 | 功能说明 |
| `author` | 否 | 作者或组织说明 |

入口类必须公开、非抽象、非开放泛型，实现 `IDocumentImporter`，并具有公开无参构造函数。构造函数宜保持简单，实际文档读取放在 `ReadAsync` 中。

插件 `id` 按不区分大小写检查唯一性。如果两个文件夹声明相同 `id`，两者都会显示重复错误，不会自动挑选较新版本。`version` 用于展示；接口是否兼容由 `apiVersion` 和共享契约程序集版本检查决定。

同一个扩展名可以由多个不同 `id` 的插件支持，宿主会提供导入器选择。一个插件的清单、依赖或入口类型加载失败，会显示在插件管理中，不影响其他正常插件。

## 四 接口与返回数据

契约程序集是 `DictationAssistant.Plugin.Abstractions.dll`。入口方法如下：

```csharp
public interface IDocumentImporter
{
    Task<ImportDocument> ReadAsync(
        Stream content,
        string fileName,
        CancellationToken cancellationToken);
}
```

`content` 是宿主打开的输入流。`fileName` 是用户选择的文件名，用于扩展名检查和来源提示；不要把它假定为可直接访问的完整本地路径。

### ImportDocument

| 属性 | 类型 | 含义 |
|---|---|---|
| `Sections` | `IReadOnlyList<ImportSection>` | 按预期阅读顺序排列的表格或正文分区 |
| `SuggestedSectionIndex` | `int` | 默认选中的分区索引，从 `0` 开始 |
| `Warnings` | `IReadOnlyList<string>` | 可供用户核对的提示，例如重复表格、被忽略的图片 |

### ImportSection

| 属性 | 类型 | 含义 |
|---|---|---|
| `Name` | `string` | 分区名称，例如“表格 1”或“正文段落” |
| `Kind` | `ImportSectionKind` | `Table` 或 `Paragraphs`；默认值为 `Table` |
| `Columns` | `IReadOnlyList<string>` | 列名；无表头时可使用“第 1 列”等名称 |
| `SuggestedColumnIndex` | `int` | 默认提取哪一列，从 `0` 开始 |
| `Rows` | `IReadOnlyList<ImportRow>` | 分区内的原始行 |

有“单词／词性／中文释义”三列时，英文列索引是 `0`，中文列索引是 `2`。若前面还有“序号”列，英文列索引则为 `1`。`Kind` 务必正确填写，正文标题和姓名栏应放在 `Paragraphs` 分区，才能在“所有表格”模式中被排除。

### ImportRow

| 属性 | 类型 | 含义 |
|---|---|---|
| `SourceLabel` | `string` | 人可读的来源，例如“表格 1，第 2 行” |
| `Cells` | `IReadOnlyList<string>` | 本行的各列文字，与 `Columns` 的顺序一致 |
| `IsHeader` | `bool` | 本行是否为表头，默认 `false` |

这些集合和其中的字符串不能为 `null`。每行单元格数不得超过分区列数；建议用空字符串补齐缺失列，避免错位。可以保留表头作为一行并标记 `IsHeader=true`，由用户决定是否跳过。

全部索引采用零起点。宿主会将越界的推荐索引限制到有效范围，但插件仍应返回正确值。来源标签中的“第 1 行”是显示文字，可以采用更自然的一起点编号。

## 五 宿主如何生成听写词表

插件返回数据后，`DocumentImportService` 验证结构并复制集合。`ImportPreviewBuilder` 根据用户选择生成一行一个词条的纯文本。插件不应预先按宿主默认选项删除其他列、重复词或表头，否则用户无法在预览中更改选择。

| 预览选项 | 默认规则 |
|---|---|
| 分区 | 采用插件建议的分区 |
| 自动选列 | 对每个分区分别使用 `SuggestedColumnIndex` |
| 跳过表头 | 默认开启，排除 `IsHeader=true` 的行 |
| 去重 | 默认关闭；开启后保留规范化文本的首次出现 |
| 去行首编号 | 默认开启，可在预览中关闭 |

“所有表格”对应内部 `SectionIndex=-1`：文档有 `Table` 时，只合并这些分区；完全没有表格时，合并正文分区。合并顺序与 `Sections` 的顺序一致，不会自行排序。

**手动选列是按列序号应用于所有选中的表格。** 例如手动选择第 4 列，就读取每张表格的第 4 列；不会按“中文释义”这个列名重新匹配。不同表格的布局不一致时，建议分别导入，或使用各表独立的推荐列。缺少所选列的行会作为空项跳过。

一个选中单元格保持一个词条。宿主将连续空白、制表符和换行压为一个普通空格，并清理两端空白。例如单元格内的 `take`、换行、`part in` 会变成 `take part in`。如果一个单元格实际包含多个独立词条，插件应主动把它们拆成多行；宿主不会自行猜测。

去重发生在空白和编号处理之后，采用区分大小写的完整字符串比较。因此 `Monday` 与 `monday` 仍是不同条目；同样内容位于不同表格时，开启去重可合并为首次出现的一条。

行首编号处理支持最多 6 位数字，规则如下：

| 输入示例 | 开启去编号后的结果 |
|---|---|
| `1. apple` | `apple` |
| `1、apple` | `apple` |
| `1．apple` | `apple` |
| `1)apple` | `apple` |
| `(1) apple` 或 `（1）apple` | `apple` |
| `1.apple` | 保留原文，英文点后没有空格 |
| `3.14`、`3D`、`21st` | 保留原文 |

导入预览的修改只在用户确认后应用。替换和追加都会先结束当前播报、重置进度，然后更新编辑器中原来的 `TextDocument`，作为一次可撤销操作。后续随机顺序和播报使用更新后的词表。

## 六 输入流 取消与错误处理

**输入流归宿主管理。** 插件只读取它，不关闭它，也不在方法返回后继续使用它。使用 `StreamReader`、`ZipArchive` 等包装器时设置 `leaveOpen:true`；插件自己创建的临时流或解析器由插件释放。

返回数据需要完全物化，例如数组或已经填充好的列表。不要返回依赖仍打开文档的延迟枚举，也不要返回后在后台继续修改 `Sections`、`Rows` 或 `Cells`。

宿主在工作线程运行读取，并对同一个已加载插件实例串行调用。用户切换导入器或取消后，旧读取可能仍在退出；新的同实例读取会等旧任务结束，不会与它并发。不同插件实例之间可以并发，公共静态状态仍应考虑线程安全。

取消采用合作方式：把 `CancellationToken` 传给支持取消的读取方法，并在行循环和较长的解析循环中调用 `ThrowIfCancellationRequested()`。收到取消时让 `OperationCanceledException` 正常向上传递。不要将取消吞掉后返回旧结果。

宿主会等待实际的插件任务完成后再释放输入流，即使预览窗口已经请求取消。它不能强制中断不合作的托管插件；若插件忽略取消并长时间运行，用户可能需要重启应用。

对于损坏文件、格式不支持或超限，抛出带清楚说明的 `InvalidDataException`。依赖缺失等加载错误显示在插件管理中；读取错误显示在导入界面。格式解析应限制压缩展开大小、XML 深度或记录数，避免把普通错误变成主程序的资源耗尽。

## 七 宿主与 DOCX 插件的限制

以下是当前宿主代码的结果验证上限，超限会拒绝导入：

| 项目 | 宿主上限 |
|---|---:|
| 输入文件大小预检查 | 可定位流为 64 MiB |
| 分区总数 | 512 |
| 提示总数 | 512 |
| 每分区列数 | 1–256 |
| 所有分区的总行数 | 100,000 |
| 所有返回文本字段累计长度 | 16,000,000 |
| 单个单元格文本长度 | 200,000 |
| 分区名、列名、来源标签各自长度 | 2,000 |
| 每条提示的长度 | 10,000 |

文本长度按 .NET `string.Length` 计算，累计值包括单元格、列名、分区名、来源标签和提示。宿主对不可定位的输入流不能通过 `Length` 预检大小；插件仍需根据自己的格式实施实际读取限制。

正式 DOCX 插件另有更严格的格式限制：输入实际读取最多 64 MiB，正文 XML 实际解压字节最多 32 MiB，XML 字符最多 33,554,432，节点深度最多 128，ZIP 项目最多 4096；外层表格最多 256 张，每表最多 256 列，总输出最多 50,000 行、500,000 个补齐后的单元格。DTD 被禁止，XML 外部资源解析被禁用。最终能否导入，需要同时满足插件和宿主的限制。

## 八 正式 DOCX 插件可参考的实现

完整源码位于 `plugins/DictationAssistant.Importers.Docx/`。它不需要安装 Microsoft Word，直接读取 DOCX 包中标准位置 `word/document.xml`，支持 Transitional 与 Strict 两种 WordprocessingML 命名空间。

它保留外层表格的行顺序、大小写、原始单元格及重复项；识别前 10 行内的常见表头，并保留 Word 显式表头标记。横向合并单元格的文字只出现在起始列，后续跨度补空字符串；嵌套表格文字合并到所属单元格，不另生成重复分区。正文中不属于表格的非空段落独立返回。

白色或显式隐藏文字仍会被读取，并返回提示。这一点对练习副本尤其重要：看起来空白的答案格可能只是将字体设为白色。插件发现文字相同的表格时也只提示，不自动删除整张表格。

本次“第二周听力词汇.docx”有两张相同的 40 词表，第二张英文答案是白色字体。默认选择第一张表格的“单词”列并跳过表头，得到 40 词；选择所有表格并保留重复项，得到 80 词；姓名和得分栏位于正文分区，不混入所有表格。

当前 DOCX 解析范围有明确界限：

- 读取正常正文与表格文字，不进行 OCR，因此扫描图片中的文字无法提取。
- 不读取旧版二进制 `.doc`，需要用户先另存为 `.docx`。
- 不解析页眉、页脚、批注、脚注、尾注、图片中的文字、文本框或嵌入对象。
- 跳过删除修订和域指令，不执行宏，也不打开链接或 OLE 文件。
- 单元格中的多段文字会在预览阶段合并为空格分隔的一条；复杂教学排版可能需要用户手动调整预览，或编写专用解析插件。

## 九 构建 安装与更新

在 SDK 根目录打开 PowerShell，构建示例：

```powershell
dotnet publish .\examples\PhrasesImporter\PhrasesImporter.csproj -c Release -o .\artifacts\example-phrases
```

在完整源码根目录中，对应命令是：

```powershell
dotnet publish .\sdk\examples\PhrasesImporter\PhrasesImporter.csproj -c Release -o .\artifacts\example-phrases
```

正式 Word 插件可从完整源码单独构建：

```powershell
dotnet publish .\plugins\DictationAssistant.Importers.Docx\DictationAssistant.Importers.Docx.csproj -c Release -o .\artifacts\docx-vocabulary
```

这些都是普通托管类库，无需将 .NET 运行时复制到插件目录。如果插件增加原生库，应提供与当前 Windows 应用架构匹配的私有依赖，并保留发布输出中的相对目录。

安装或更新按以下顺序进行：

1. 退出 DictationAssistant。
2. 将完整发布文件夹复制到应用的 `Plugins` 中，例如 `Plugins/example-phrases/`，确认其下直接有 `plugin.json`。
3. 一起保留入口 DLL、`.deps.json` 和所需私有依赖。不要把 `DictationAssistant.Plugin.Abstractions.dll` 作为插件私有 DLL 一起复制。
4. 重新启动应用，进入“插件 → 插件管理”检查加载状态。
5. 使用“从文档提取词表”选择对应扩展名的文件，在预览中确认分区、列、条数和内容，再替换或追加到编辑器。

运行期间替换、移除或新增 DLL 不会热更新。卸载时先退出应用，再删除该插件文件夹。更新时替换同一个插件目录；不要同时保留相同 `id` 的旧版本副本。

## 十 依赖隔离与主程序发布

宿主为每个插件使用独立的、不可卸载的 `AssemblyLoadContext`，优先依据插件自己的 `.deps.json` 解析依赖，也可从同一插件目录寻找直接放置的私有 DLL。它不会到另一个插件目录中寻找依赖。共享契约始终返回宿主已经加载的程序集实例；系统运行时程序集由默认上下文提供。

这种安排减少不同插件私有依赖版本之间的冲突，但**不构成安全沙箱**。插件代码与应用在同一个进程中运行，拥有应用可用的权限。只安装来自信任来源、已了解用途的插件。本次提供的示例和 DOCX 插件均在本地解析，不上传文档。

不要在插件中引用整个 `DictationAssistant.App` 以获取窗口或服务。共享依赖应以插件契约为边界；只使用系统基础类库时，可直接参考本指南的示例。若引入新的框架依赖，需要确认宿主已提供相应框架，不能假定插件声明后主程序就会自动安装它。

主程序使用动态程序集加载，因此保持以下发布设置：

```xml
<PublishTrimmed>false</PublishTrimmed>
<PublishAot>false</PublishAot>
```

当前 `DictationAssistant.App.csproj` 已设置这两项。不要为缩小体积覆盖它们：运行时才侧载的程序集无法在主程序编译时完整分析；Native AOT 也不支持这种动态加载方式。参见 Microsoft 的[裁剪不兼容模式说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/trimming/incompatibilities)和[Native AOT 限制](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)。

## 十一 常见问题

| 现象 | 检查方法 |
|---|---|
| 插件管理看不到正确入口 | 检查文件夹层级；`plugin.json` 应在 `Plugins` 的直接子文件夹中 |
| 提示缺少 `plugin.json` | 复制完整发布输出，避免只复制 DLL |
| 提示入口类型无效 | 检查完整命名空间、类是否公开、是否实现接口、是否有公开无参构造函数 |
| 提示接口版本不匹配 | 使用当前 SDK 的契约 DLL，保持 `apiVersion=1`；不要自行重编译同名接口来替代宿主契约 |
| 提示 DLL 或私有依赖缺失 | 检查 `entryAssembly` 名称及 `.deps.json`、依赖 DLL、原生资源是否完整 |
| 提示 `id` 重复 | 退出程序，只保留一个对应版本的插件文件夹后重启 |
| 正文标题混进全部表格 | 检查正文分区是否标为 `ImportSectionKind.Paragraphs` |
| 提取到了词性或中文而不是英文 | 检查列顺序和从零开始的 `SuggestedColumnIndex` |
| 词条数量翻倍 | 检查是否存在练习副本或重复表格；默认选择单表，或由用户开启去重 |
| 一格中的几个词合成一行 | 宿主按一单元格一词条处理；插件需先拆成独立 `ImportRow` |
| 取消后仍在等待 | 确认解析过程检查取消标记，没有吞掉 `OperationCanceledException` |

本指南和示例使用的准确类型、默认值与校验逻辑，以源码中的 `IDocumentImporter.cs`、`PluginCatalog.cs`、`PluginLoadContext.cs`、`DocumentImportService.cs` 和 `ImportPreviewBuilder.cs` 为准。示例代码遵循源码包的 AGPL-3.0-or-later 许可，完整条款见源码包的许可证文件。

## 练习插件扩展（同一接口程序集，兼容文档插件 v1）

`IDocumentImporter` 及既有 `apiVersion:1` 清单保持不变。新增的练习插件使用 `IPracticePlugin`：

```csharp
public interface IPracticePlugin
{
    Task RunAsync(IPracticeHost host, CancellationToken cancellationToken);
}
```

练习插件 `plugin.json` 指定 `"kind": "practice"`、`"extensions": []`、`"apiVersion": 1`；旧文档插件省略 `kind` 时仍按 `"document-importer"` 处理。

宿主 `IPracticeHost` 提供不可变词表、自动播报次数、间隔计算、逐词的等待播放任务和窗口所有者；插件在 `RunAsync` 内实现练习窗口、计时、记录和结果展示。插件禁止在音频播放任务尚未完成时开放输入。窗口关闭前必须取消和等待当前播放任务。支持此接口的主程序需重新编译；不能将练习 DLL 单独安装在旧二进制版本上。

参考实现：`plugins/DictationAssistant.Practices.Typing`。C# SDK/宿主目标框架均为 `net10.0`。宿主加载 Avalonia 程序集时共享默认加载上下文，以免出现两份不兼容的 `Window` 类型。
