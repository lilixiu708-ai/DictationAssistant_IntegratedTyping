# Windows 侧载插件扩展：构建与验证记录

> 历史记录：本文仅记录早期 `0.0.0-plugins.1` DOCX 导入版。以下 SDK、包内容和验证结果不代表当前同步打字版；当前功能、构建命令和验证范围见 [项目首页](../README.md)，文档入口见 [文档索引](README.md)。

日期：2026-10-19。自定义构建：`0.0.0-plugins.1`，Word 插件：`1.0.0`，接口：v1。

## 来源与实现范围

原项目为 <https://github.com/ArcticLampyrid/DictationAssistant>。实际代码基于本会话上传的 `DictationAssistant-4.x.zip` 快照，继承此前已经完成的随机顺序扩展；没有把未核对的远程提交当作修改基准。原始源码 ZIP SHA-256：`cd83477ac3b925d5bfe5aac9214f0382d006cd92879d5e2485bac9028b042679`。

本次新增：

- 独立共享契约程序集 `DictationAssistant.Plugin.Abstractions`，保留主应用原有单体架构。
- 每个第一层插件文件夹的 `plugin.json` 清单和独立 `AssemblyLoadContext`。宿主仅引用契约，不引用 Word 插件项目或 DLL。
- 插件管理、异步文档读取、表格及列选择、可编辑预览、可撤销替换与追加。
- 文件打开、启动路径及拖放共用同一文档路由；没有导入器的文档不会被当成 TXT 读取。
- 独立 BCL 实现的 `.docx` 插件，不新增 NuGet 依赖、不依赖 Office 自动化。
- 与 GUI 共用契约、读取服务及预览规则的批量提取命令行。
- 可编译的 `.phrases` SDK 示例，以及 Windows 发布脚本和中文文档。

宿主逐插件串行调用读取器，保留输入流到真实读取任务完成，取消采用合作方式。导入确认后，等待旧播放队列结束并归零，然后更新原 `TextDocument`，避免播放器仍持有旧文档或旧顺序。一次替换、追加或随机重排分别形成一次撤销。

## 附件提取核对

原文档 `第二周听力词汇.docx` SHA-256：`ca3f6d93a3cd817a4f21b5f59fa4193803837605899436e940943d306494e40c`。提取前后保持一致。

独立审阅 OOXML 结构得到两张相同的 41 行 × 4 列词表，第一行为表头；第二张英文为白色文字。英文列共 80 条记录、40 个不同词条。正文中的 `Week 2`、姓名及得分栏单独存在，不应混入“所有表格”。

实际使用宿主和侧载插件运行提取，逐行与独立结构核对结果比较：

| 选择 | 实际条数 | 内容核对 |
| --- | ---: | --- |
| 默认第一表 + 推荐英文列 | 40 | 完全一致 |
| 第一表 + 第四列中文释义 | 40 | 完全一致 |
| 所有表格 + 推荐列 | 80 | 完全一致，重复项保留 |
| 所有表格 + 推荐列 + 去重 | 40 | 完全一致，移除 40 个重复项 |

大小写、词组和中文释义均保留。`ambiguous` 的尾随空格被整理；正文标题和序号列未混入默认英文输出。以上四组既在同源码 Linux 构建执行过，也直接对最终 Windows 发布目录中的托管 `DictationAssistant.App.dll` 和插件 DLL，在 Linux .NET 运行时下使用临时运行配置执行过。后者验证的是同一发布产物的托管提取路径，不是 Windows EXE 的原生桌面运行。

## 真实 GUI 检查

使用同一功能源码的 Linux 构建，在隔离 Xvfb 中运行真实 Avalonia 窗口，通过鼠标、键盘操作逐次检查，没有新增自动测试工程。

| 操作 | 实际结果 |
| --- | --- |
| 通过启动参数打开中文路径 DOCX | 显示导入预览，默认表格 1、推荐列、40 条 |
| 选择“所有表格” | 显示 80 条，跳过两行表头 |
| 勾选精确去重 | 显示 40 条，并显示移除 40 条重复 |
| 切换中文释义列 | 显示完整中文释义，数量符合选项 |
| 确认替换词表 | 主编辑器显示 40 条，状态与播报进度归零 |
| Ctrl+Shift+R | 实际触发随机重排，整条词语移动 |
| 连续 Ctrl+Z | 撤销随机重排、再撤销导入，恢复导入前空词表 |
| Ctrl+Shift+I | 打开原生文件选择器；选择 DOCX 后进入同一预览 |
| 已有一条 `existing entry` 后追加 | 旧词条留在首行，40 条新词条从第二行开始 |
| Ctrl+Z 撤销追加 | 恢复只有 `existing entry` 的原词表 |
| 插件菜单及插件管理窗口 | 显示 Word 插件 v1.0.0、接口 v1、已加载状态、目录及安装说明 |

无窗口管理器的虚拟显示需要显式设置 X11 焦点；该环境下未取得可靠的剪贴板读回。因此 GUI 的撤销、追加等以实际画面核对，完整内容逐行比较使用同一宿主/插件的命令行输出。未把失败的剪贴板读回列为通过项目。Windows 文件对话框和拖放行为进行了源码及编译检查，本次没有 Windows 原生桌面实测。

## 独立侧载验证

1. 编译 SDK 的 `Example.PhrasesImporter.dll`，放入新的插件子文件夹，宿主代码不作改变。
2. 同时放入一份损坏 JSON 清单：目录报告两个有效插件正常加载，损坏清单独立显示错误。
3. 调用示例提取器读取四条短语，实际得到 `look after`、`take part in`、`keep in touch`、`3D model`。编号清理覆盖英文点号、无空格中文顿号和括号；`3D` 没有被误删。
4. 临时移走插件，目录显示零个已加载项；尝试读取 DOCX 明确报告缺少导入器，退出码 1，没有生成输出文件。
5. 恢复 Word 插件。诊断用示例和坏清单未进入最终 Windows 程序包。

接口版本、重复 ID、入口路径及共享契约类型检查经过源码复读；没有把每一种可能的坏插件情形都声称为实际动态验证。

## 验证边界

- **未在真实 Windows 桌面运行交付 EXE。** Windows 编译、发布、文件格式及托管提取路径已检查，GUI 实测来自 Linux 同源码构建。
- 没有验证真实 Windows SAPI 发声、扬声器听感或所有在线语音服务，也没有完成真实音频导出的端到端试听。本次新功能不修改这些原有语音实现。
- Windows 同步 SAPI 合成已经开始时，归零可能要等待该次合成返回；新词表会在等待完成后提交。
- DLL 插件在宿主进程中运行；依赖加载分组不是安全沙箱。取消需要插件配合，无法强行终止任意插件代码。
- 附带 DOCX 插件不做 OCR，不读取 `.doc` 或加密文档，不覆盖复杂 Word 排版的所有情况。提取前应使用预览核对。
- Windows 发布者签名未提供。本包为自定义扩展构建，非上游官方发行版。
