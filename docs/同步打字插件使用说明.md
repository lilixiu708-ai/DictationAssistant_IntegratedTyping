# DictationAssistant 4.x — 同步打字 DLL 插件（Windows x64）

本文说明当前源码中的操作流程；对应版本的构建、发行与验证结果以 Release、Actions 和验证记录为准。云环境验证不能替代 Windows 实际音频和输入法检查。

当前正在准备 `typing.5`（R5）本体和同步打字插件 1.1.0 的独立预发布。Avalonia/MS-PL 组合授权路径仍未解决，将在发行说明和随包文件中披露；原始许可与对应源码交付要求继续保留，详见[版权与许可审计](版权与许可审计.md)。

本项目以原版 `DictationAssistant`（C# + Avalonia）为基础，保留原窗口、SDL 音频播放器、Word 导入插件和随机重排，在插件接口中新增独立 `SynchronousTyping` 练习插件。原项目许可证 AGPL-3.0-or-later 及声明保留。

轻量化包仍自带 .NET 运行环境，无需另装运行库。升级时请解压到新的空文件夹，再打开原有词表，以免旧版插件目录中的多平台运行库继续占用空间。

## 你要求的听写流程

1. 先使用原软件编辑词表（每行一条），或从 `.docx` 导入。空白行忽略，重复词条保留。需要先乱序，可点击「打乱顺序」或 `Ctrl+Shift+R`。
2. 设置原程序右侧「自动播报次数/词」及「自动播报间隔/秒」，例如 2 次和 2 秒。选好英文语音、音量和语速。
3. 打开原窗口「插件 → 同步打字练习」或 `Ctrl+Shift+T`。程序在后台读取并核对当前词表，成功后显示「已读取 实际数量 / 理论数量 条」，例如「已读取 40 / 40 条」；再设置每词打字时限（默认 10 秒，可选 1–300 秒）以及是否忽略大小写。
4. 点击「开始练习」后，从第一次播放到最后一次语音结束，包括重复间隔，都显示 **「播放中」**，不露出答案或打字框。
5. 最后一次**实际音频播放结束**后才出现打字框，并开始计时。倒计时上方不再显示下划线占位条；最后一次播报结束后不再额外等待 2 秒。
6. 按 Enter 提前记录；超时自动记录当前输入，空白也可记录。每个词**不立即显示对错**。
7. 顶部进度条显示已完成的词条数量。全部词条结束后统一显示正确率，成绩区逐词列出正确词条、你的输入和结果；可滚动查看全部记录，并导出 UTF-8 BOM 的 CSV。滚动成绩时，顶部摘要和底部导出、关闭按钮保持可见。

例：`Monday` → `[播放中 1/2]` → `[等待 2 秒，仍显示播放中]` → `[播放中 2/2]` → `[输入框 + 10 秒]` → `[只记录]` → 下一个词。

准备页的介绍文字放大为 18 号并居中，倒计时和本轮完成进度条在开始前隐藏；开始练习后保留进度条，用于查看已完成数量。

## 翻译提示与提前翻译

宿主词表仍按每行一条填写原词或短语，作为播报内容和正确答案；不要在宿主词表中追加翻译。同步打字插件 **1.1.0** 在准备页提供「录入／提前翻译」，打开后按“原词 + Tab + 译文”两列编辑，也可以从电子表格复制两列粘贴。原词须保留当前词表中的大小写和标点；重复原词共用一份译文，译文留空可删除该词的提示。

点击「保存」后，译文写入本机文件，其他词表已保存的翻译会保留：

```text
%APPDATA%\DictationAssistant\Plugins\SynchronousTyping\translations.json
```

「显示翻译提示」默认关闭，可在练习时随时勾选或取消。提示只在每词全部播报结束后的打字阶段显示；没有译文的词条不显示提示。显示与隐藏均不改变播报内容、正确答案或评分规则。手动录入与查看已保存译文不需要网络或 API 密钥。

需要自动补全时，先打开独立的「翻译 API 设置」窗口。目前支持 **DeepL API Free / Pro**，须选择与密钥对应的账户类型；输入框遮挡密钥，已有密钥不会回填显示。

- **保存并使用**：Windows 以 DPAPI 当前账户加密，并加入本机 Windows 标识派生的绑定信息，将密文保存为同目录下的 `translation-api.json`；复制文件到其他机器或账户不能直接读取。
- **仅本次使用**：本次编辑窗口关闭后不再保留这份会话配置，不写入密钥文件。Linux 等不支持 Windows DPAPI 的平台只提供此方式。
- **删除本机绑定**：删除本机保存的密钥配置。窗口只展示机器标识的短摘要，不显示原始标识；机器标识不会发送到 DeepL。

系统加密用于降低本地配置文件泄露的风险，不能防止已控制当前账户或程序进程的软件读取使用中的密钥。不再依赖聊天中的密钥或环境变量自动绑定。

配置完成后，在翻译编辑窗口选择 **英译中 / 中译英**，点击「翻译缺失项」，只将尚未填写译文的原词发送到所选 DeepL 服务；已有译文保留。结果先填回编辑器，校对后点击「保存」。练习开始后不再调用翻译服务，也不会在打字或倒计时过程中等待翻译。

本次翻译界面已在 Linux 虚拟图形会话中核对：录入与保存、重新打开后恢复、打字时显示/隐藏提示、缺少密钥时的提示，以及原词判分与结算文字删除。两词练习使用本地 WAV 和 SDL dummy 音频输出，均按原词判为正确；未验证真实扬声器。API 设置窗口已核对空密钥校验、掩码输入、临时使用不产生密钥文件，以及再次打开不回填密钥；未向 DeepL 发送测试密钥。Windows DPAPI 保存及跨机器/账户拒绝读取、真实 DeepL 鉴权翻译仍须实机验证；构建通过不代表系统加密或外部服务已验证。

## 后台读取与异常日志

理论数量来自进入练习时当前编辑器的词表快照，按非空行统计，重复词条分别计数；实际数量是练习插件成功读取并核对的词条数。这项检查核对当前词表到练习的传递，不检测原 DOCX 在导入之前或导入过程中是否已经缺词；原文完整性仍需在导入预览中核对。

读取完成前不能开始练习。发现数量不符、词条无效或读取失败时，程序禁用「开始练习」，显示错误并自动尝试保存 crash log。Windows 日志目录为：

```text
%APPDATA%\DictationAssistant\Plugins\SynchronousTyping\CrashLogs
```

日志记录失败阶段、实际和理论数量、失败词条的序号（从 1 开始，能够定位时）、版本及异常详情，保留最近 20 份。程序不主动附加整份词表或作答内容；第三方异常详情仍可能包含词条或文件路径，分享日志前请自行检查。

## 不通过 PowerShell 获取可执行成品（推荐：GitHub Actions）

已提供 `.github/workflows/build-typing-windows.yml`。将**解压后的源码树本身**发布到你自己的 GitHub 仓库（不能只上传 ZIP 文件），使用 GitHub 的 Actions 服务编译，不需要在 Windows 电脑上安装 SDK，也不需要运行 PowerShell。可用 GitHub Desktop 图形界面发布随包附带的 Git 仓库：

1. 解压 `DictationAssistant_IntegratedTyping_GitHubReady.zip`。
2. GitHub Desktop → `File → Add local repository...`，选择解压得到的源码目录（其中有 `.git` 文件夹）。
3. 点击 `Publish repository`，发布到你的 GitHub 账户。私有仓库亦可，但需要账户有 GitHub Actions 可用额度。不要发布自己的其他私人文件。
4. 打开该仓库的 `Actions → Windows desktop app with preinstalled typing plugin → Run workflow`。如果 push 到 `main` 后自动开始，也可以直接查看该次运行。
5. 普通分支构建是否上传二进制取决于审核条件。精确的 R5 标签使用已明确披露许可未解决项的发布路径，生成本体和两个插件的独立 Release；绿色构建与 Release 公开状态应分别核对，不把尚未上传的产物说成可下载。
6. 将该 ZIP 完整解压到 Windows 文件夹，双击 `DictationAssistant.App.exe`。这是带 .NET 运行环境和两个 DLL 插件的桌面程序，不打开网页。

GitHub Actions 如果显示 `failed`，请把错误日志发来继续修复。**在绿色完成之前不能保证源码能编译运行**。CI 会自动测试重复播放等待与判分，并核对打包后的两个 DLL 与 `plugin.json`。

## 已有 .NET 10 SDK 与 Python 3.11+ 的 Windows 电脑（纯 CMD，无 PowerShell）

解压源码，双击 `build-windows-typing.cmd`。构建成功后使用 `artifacts/Windows-x64/DictationAssistant.App.exe`，也会生成 `artifacts/DictationAssistant_IntegratedTyping_Windows_x64.zip`。

首次还原 NuGet 依赖必须联网。本地若没有 SDK，脚本会明确提示使用 GitHub Actions；它不会调用 PowerShell，也不会假装完成编译。

新版不再携带 BASS。本地音频资源可使用 WAV（PCM/浮点）、MP3/MPEG 或 AIFF；Windows 上其他格式依赖系统 Media Foundation 解码器，不能保证每台机器都有 FLAC、AAC、Opus 或 APE 支持。升级后应重新核对现有音频资源，无法解码时会尝试所选语音引擎。

## 成品布局（CI 成功后才会生成）

```text
DictationAssistant.App.exe
DictationAssistant.App.dll
DictationAssistant.Plugin.Abstractions.dll
Plugins/
  DocxVocabulary/
    plugin.json
    DictationAssistant.Importers.Docx.dll
    （其他依赖）
  SynchronousTyping/
    plugin.json
    DictationAssistant.Practices.Typing.dll
    （其他依赖）
```

同步打字为**独立的 .NET DLL 侧载插件**，不是浏览器应用，不能把 DLL 直接放入没有练习插件接口的旧 EXE。修改后的宿主会加载 `kind=practice`；原来的 `IDocumentImporter` Word 接口保持兼容。插件管理可以查看加载失败原因。第三方插件运行时拥有与程序相同的权限，**不是安全沙箱**。

独立插件更新时先关闭程序，再以完整的 `SynchronousTyping/` 或 `DocxVocabulary/` 目录替换 `Plugins/` 下对应目录并重启；不要只复制主 DLL。1.1.0 同步打字插件要求宿主功能级别 3，译文与 API 加密设置保存在用户 AppData，替换插件目录不会删除它们。插件包、源码与校验和使用各自的 Release，版本不与本体同步递增。

## 验证范围与音频注意

既有版本已完成 .NET 10 编译、15 项打字逻辑检查、两插件加载、DOCX 提取、Windows 自包含包校验及 GitHub Actions 构建；Linux 虚拟图形会话也用于菜单、练习取消和退出检查。新增界面与读取核对的验证结果按对应提交记录，不能从历史版本的成功结果推定。

本次界面改动已在 Linux 虚拟图形会话核对：正常读取 `2 / 2`、含空行和重复词条时读取 `3 / 3`、介绍居中、取消下划线、倒计时、Enter 提交及超时结算正常。实际语音合成失败时，界面显示错误和日志路径，并生成带阶段、计数及异常详情的日志；读取数量不符和日志保留上限未通过运行故障触发验证。

**真实 Windows 启动、SDL/SAPI 扬声器试听、中文输入法及资源占用仍需实机验证。** 真实音频设备可能存在驱动缓冲延迟，需实际试听确认。

历史构建报告曾指出原项目所依赖的部分 NuGet 包有安全告警；本改动没有未经核实地升级它们。不要从不信任来源安装插件。
